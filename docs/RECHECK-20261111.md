# MoonFixture 0.1.3 补丁专项复查

日期：2026-11-11。此次在 `0.1.2` 的兼容性维护之后补查边界输入，发现并修复三类问题；没有增加新的生成器、值类型或数据库驱动。下述结果来自 Windows 本地执行，不能据此推断补丁已发布或新提交的远程 CI 已通过。此前 `0.1.2` 的维护记录保留其原始测试数量与版本。

## 复现与修复

### 唯一引用的空父键

最小模型包含一个 `Constant(Null), unique=true` 父键和一个 `Reference(parent, key), unique=true` 子字段。`0.1.2` 的编译、生成均成功，但生成的子字段为 null，随后 `validate_dataset` 报告 `unexpected_null`。普通非唯一 Reference 则会报告 `invalid_reference_key`。

补丁在唯一引用域遇到实际缺失或 null 父键时使用普通 Reference 的检查路径，避免将 null 作为有效引用值抽出。回归覆盖常量 null、复制派生的 null、普通/唯一引用、按自身配置始终为空的子字段，以及一次尝试填满有效唯一引用域。常量、复制、查值本身允许生成 null，SQL 风格 UNIQUE 允许多个 null，这些语义保留。

### JSON 整数的精确检查

`0.1.2` 将模型 `count:1e-400` 解析为 0，将数据集值 `1.0000000000000001` 导入为 `Integer(1)`；后者甚至可以通过期望常量 1 的模型校验。原因是整数判断发生在 Double 舍入之后。

模型、数据集、重放清单三个文本入口现在保留 JSON 数字原文。私有解析器根据十进制系数、小数位与指数判断数学上的整数值，再检查 Int32 范围；没有展开指数长度的零字符串。指数累计在超过输入长度加十后饱和，避免大指数溢出；工作量随受输入限制约束的文本长度线性增长。

`1.0`、`1e2`、`100e-2` 和合法的带指数零仍可接受；非零分数、Int32 越界值及非法 JSON 数字被拒绝。回归包含正负 Int32 边界、超长指数、含 2048 个尾随零的系数与负指数精确抵消、三个文本入口，以及程序化 Json 整数和不一致数字表示。值域仍为 Int32，不提供任意精度数值或浮点金额。

### SQLite 导出名称

`0.1.2` 对表名 `Users`/`users`、同表列名 `id`/`ID` 或表名 `sqlite_records` 均返回成功的 SQLite 包；实际 SQLite 分别报告表已存在、列名重复及内部保留名称错误。

`sqlite_bundle` 现在在导出前检查 ASCII 大小写重名与 `sqlite_` 保留前缀，返回 `sqlite_duplicate_table`、`sqlite_duplicate_column` 或 `sqlite_reserved_name`。这些检查仅作用于 SQLite 适配层；名称区分大小写的 JSON 模型仍然可以编译、生成和校验。回归同时保留合法引用、可空字段、`sqliteX` 表名及带 `sqlite_` 前缀的普通列名。
